# Контракт оболочки сервера

Развертывание Production и staging CI не должно получать root-доступ. Обертка, принадлежащая root и недоступная для записи пользователем-разработчиком, является единственной точкой входа для sudo.

Требуемые имена оболочек:

- `vatrushka-preflight`
- `vatrushka-deploy`
- `vatrushka-rollback`
- `vatrushka-observability-deploy`
- `vatrushka-runtime-status`
- `vatrushka-publish-updater`

Каждый обёртка проверяет путь манифеста в белом списке и контрольную сумму, принадлежащую корню, запускается с `set -eu`, не передаёт секретов, сохраняет строку аудита с идентификатором версии и результатом, и отклоняет произвольные аргументы оболочки. Скрипты в `bin/` являются версионированным исходным кодом; `install.sh` — единственный поддерживаемый установщик.

CI загружает манифест кандидата и его gzip-архив исходного кода только в `/var/lib/vatrushka/inbox/`. Имя файла архива — `<sourceArchiveSha256>.tar.gz`. `vatrushka-preflight` является фиксированным привилегированным импортером: он проверяет обычные файлы, принадлежащие пользователю-развертывателю, проверяет содержимое архива и контрольную сумму, копирует манифест и архив в отдельные адресуемые по содержимому хранилища, принадлежащие root, проверяет контракт кандидата и выводит канонический путь манифеста. `vatrushka-deploy` принимает только этот канонический путь. Ни один пользователь CI не может напрямую записывать в любое из защищённых хранилищ.

`drivers/compose-digest-deploy` установлен с правами root, принадлежащими `install.sh`, но не может действовать до тех пор, пока оператор не создаст `/etc/vatrushka/runtime.env` из `runtime.env.example`, root-owned регистрационные учетные данные в его настроенном каталоге и `/etc/vatrushka/app.env`. Драйвер извлекает только предварительно проверенный исходный архив в каталог релиза с правами root, проверяет контрольные суммы источника и блокировки, атомарно обновляет настроенную ссылку `current`, загружает точный дайджест API и вызывает Compose с `--no-build`. Он отклоняет миграции с ручной проверкой. Отсутствующая или небезопасная конфигурация приводит к закрытию.

Тонкие оболочки намеренно не являются драйверами развертывания. `vatrushka-deploy` вызывает установленный неизменяемый драйвер доставки, а `vatrushka-runtime-status` вызывает драйвер готовности, принадлежащий root. Успешное развертывание фиксирует контрольную сумму активного кандидата и, если существует предыдущий кандидат, создает манифест отката, принадлежащий root, который ссылается только на этого предыдущего кандидата. `vatrushka-rollback` поэтому может восстановить только ранее проверенного неизменяемого кандидата и никогда не выполняет понижение схемы. `vatrushka-observability-deploy` запускает только агента телеметрии продукта, привязанного к контрольной сумме, после того как соответствующий кандидат приложения активен; он никогда не предоставляет произвольный Docker или доступ к shell.

`vatrushka-publish-updater` импортирует только контрольный манифест, принадлежащий пользователю-развертывающему, и соответствующий установщик, карту блоков, `latest.yml`, метаданные и файлы контрольных сумм из входящего контейнера. Стабильные манифесты публикуются атомарно в `/opt/vatrushka/updates`; бета-манифесты публикуются атомарно в `/opt/vatrushka/updates/beta`. CI никогда не получает прямого доступа на запись к ни одному из каталогов ленты.

Перед включением хоста в CI оператор выполняет `/usr/local/lib/vatrushka/verify-host-bootstrap --deploy-user vatrushka_deploy --environment staging` (или `production`) с правами root. Она выводит только метаданные готовности и проверяет установку оболочки, учетную запись развертывания с минимальными привилегиями, принадлежащие root файлы среды runtime/app и каталог учетных данных реестра; она никогда не отображает их содержимое.

`vatrushka_deploy` получает права sudo только для четырёх оболочек продукта после того, как этот установщик будет запущен оператором. Наблюдателю требуется отдельная учетная запись и собственный ограниченный файл sudoers; они не предоставляются через этот установщик. Его фиксированная оболочка готовности имеет версию в `ops/observer-wrappers/`.
