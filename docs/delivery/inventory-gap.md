# Нехватка запасов

Метки: **fact**, **inference**, **assumption**, **unknown**, **proposal**.

- **факт:** репозиторий содержит продукт Compose, отдельный саморазмещаемый LiveKit Compose, платформу/агента наблюдателя Compose, Linux проектный раннер и Windows проектный раннер.
- **факт:** `ops/inventory/` теперь содержит редактированную схему хоста, записи ролей и матрицу частной сети; она не содержит никаких действующих учетных данных или приватных ключей.
- **факт:** staging продолжает отслеживаться как `planned`; никаких staging runtime или активной идентичности развертывания пока нет.
- **вывод:** засекреченный инвентарь достаточен для планирования доставки, но не для активации до проверки окончательной идентичности хоста и приватного маршрута.
- **assumption:** current production VPS can become staging only after new production migration succeeds, as the ТЗ states.
- **факт (25.07.2026):** новый production VPS `vtr-prod-1` имеет Ubuntu 24.04.4 LTS, 8 vCPU, 11 ГиБ RAM и 94 ГБ свободного диска. Docker установлен, но ни контейнер продукта, ни слушатель публичного приложения не запущены.
- **факт (25.07.2026):** наследственный хост production по-прежнему запускает Vatrushka API, Caddy, PostgreSQL, Redis и LiveKit. Также на нем продолжают перезапускаться контейнеры устаревшего агента продуктовой наблюдаемости, поэтому это не чистая база staging и ее нельзя переназначать до запланированной переустановки ОС.
- **факт (25.07.2026):** устаревшие учетные записи хостов: `codex` (Docker группа, без пароля для sudo не наблюдалось), `admin` (группа sudo) и `vatrushka-deploy`; их удаление отложено до миграции production и переустановки staging.
- **неизвестно:** частные CIDR, файрвол провайдера, управление Zabbix и разрешённые пиры.
- **предложение:** добавить версионированную, отредактированную схему инвентаризации; никогда не хранить пароли, приватные ключи, сырые IP-адреса, не предназначенные для публикации в репозитории, или значения `.env`.
