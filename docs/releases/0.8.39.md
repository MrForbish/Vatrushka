# Vatrushka 0.8.39

## Product changes

- Concurrent desktop session refresh calls share a single rotation, preventing
  accidental refresh-token reuse and session-family revocation.
- Avatars, profile covers, server icons and banners load directly from private
  S3 using 15-minute presigned GET URLs. Retired CDN settings are ignored.
- README includes current Home and server voice screenshots on demonstration data.

## Delivery and migration

No database migrations, object relocation, public API changes, permission changes
or media architecture changes are required. Refresh tokens remain in Electron
main/safeStorage. The private bucket and existing attachment paths are retained.
Clients that still display cached CDN URLs should refresh their data or restart.

Release evidence is supplied by the task, assembly and release MR pipelines.
The refreshed Windows visual references are explained in
`docs/testing/2026-09-28-visual-baseline.md`; tolerances were not increased.

## Rollback

Restore the preceding verified immutable API and updater candidate using the
root-owned rollback wrapper. Do not move the release tag or overwrite release
assets. An older API will use CDN again if its legacy settings remain configured;
keep those settings disabled if CDN is still unavailable. No schema rollback is
needed. Rolling back the desktop also restores the concurrent refresh defect.
