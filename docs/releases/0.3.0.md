# Vatrushka 0.3.0

Версия 0.3.0 завершает дорожную карту от системы дизайна до стабилизации, при этом сохраняя быстрые комнаты и существующую модель самостоятельного развертывания.

## Основные моменты

- Клиент desktop теперь имеет унифицированную тёмную визуальную систему, адаптивную навигацию по серверу и регрессионно протестированные критические экраны.
- Голос отображает реальные селекторы входного/выходного устройства, громкость отдельного участника и локальное отключение звука, не влияя на других.
- Совместное использование экрана отличает мониторы от приложений windows, позволяет ведущему выбирать системный звук перед захватом и позволяет каждому зрителю управлять звуком потока отдельно. Windows запрос на циклическую передачу исключает собственный вывод Vatrushka, чтобы избежать дублирования голосов участников.
- Серверы включают текстовые/голосовые каналы, личные сообщения, иерархию ролей, наследование/разрешение/запреты для конкретных каналов и журнал аудита. API проверки остаются авторитетными, а LiveKit предоставляет ограничения на говорение и публикацию экрана/аудио.
- Аутентификация поддерживает регистрацию пароля, электронную почту/TOTP второй фактор, коды восстановления, доверенные устройства, отзыв активных сеансов и активность безопасности. Токены обновления остаются в Electron основном/safeStorage и не отображаются через предзагрузку.

## Обновление с версии 0.2.0

1. Создайте резервную копию PostgreSQL и сохраните предыдущий образ или коммит API доступным.
2. Получите исходный код версии 0.3.0 и проверьте переменные окружения относительно `.env.example` и `apps/desktop/.env.production.example`.
3. Запустите `npm ci`, `npm run db:check`, `npm run test` и `npm run build` на исходном коде релиза.
4. Разверните API. Его команда запуска применяет все ожидающие миграции Drizzle перед открытием сервера HTTP.
5. Проверьте `/health/ready`, вход по паролю/электронной почте, вкладку безопасности Сессий и доступ к существующему серверу.
6. Соберите клиент Windows с production `VITE_PUBLIC_API_BASE_URL`, затем запустите `npm run package:win` и распределите оба артефакта версии 0.3.0 по необходимости.

Все существующие миграции сохраняются. Последовательность 0.3.0 является добавочной; не удаляйте, не редактируйте, не перенумеровывайте и не объединяйте миграции, уже зарегистрированные сервером. `npm run db:check` проверяет журнал, файлы SQL и цепочку снимков без подключения к PostgreSQL.

## Откат

Остановите 0.3.0 API, восстановите предыдущий образ/коммит приложения и запустите его с той же базой данных. Добавочные таблицы и столбцы могут оставаться на месте и игнорируются более старой API. Восстановление базы данных требуется только если оператор самостоятельно выполняет разрушительное/ручное изменение схемы или данных; приложение не пытается выполнять автоматические даун-миграции.

Клиенты Desktop не обновляются автоматически, поэтому храните предыдущий установщик до тех пор, пока не будет завершена матрица носителей для двух машин.

## Контрольный список проверки

- `npm run lint`, `npm run typecheck`, `npm run test`, `npm run db:check`, `npm run build` и `npm run perf:check` проходят;
- Storybook взаимодействие/a11y, Electron E2E и Windows visual regression проходят;
- реальное переключение ввода/вывода Windows работает до и во время голосовой сессии;
- два клиента проверяют независимую громкость/отключение микрофона и звука с экрана;
- монитор и совместное использование окон приложений работают с аудио и без него, а дорожки исчезают после остановки/выхода;
- отказанные роли не могут читать/операции в приватных каналах, присоединяться к голосу, говорить или транслировать экран/аудио приложений;
- активная сессия может быть отозвана, а коды восстановления используются один раз;
- UI остаётся пригодным для использования при масштабе Windows 100%, 125% и 150%.

## Известные ограничения

- реальная доставка SMTP, захват NAT/TURN и Windows не могут быть полностью воспроизведены с помощью CI и требуют матрицу ручного выпуска;
- обновления текста и присутствия по-прежнему используют опрос вместо реального сокета;
- в серверной модерации есть кик, но нет списка постоянных банов;
- установщики не подписаны, а каналы выпуска/автоматические обновления не реализованы.
