# Vatrushka 0.7.0

Version 0.7.0 completes the current gaming UX, voice-presence and reliability scope and packages it through the protected GitLab release workflow.

## Product

- Gaming Home contains exactly four central blocks: compact voice status, quick return, active voice spaces and friends/activity from real accessible contacts.
- Authentication uses the final Vatrushka mark and approved gaming background while preserving password, email/TOTP/recovery and reset contracts.
- Home voice actions connect without hiding the server library; contact actions open the existing direct conversation.
- Public servers, server/profile media, responsive Windows title bar and updater discovery are production-ready.

## Voice and realtime

- LiveKit remains authoritative for media presence; Redis stores the recoverable voice projection and versioned server snapshots.
- Self and moderator moves are idempotent, permission-checked, pending until confirmation and available through drag-and-drop or keyboard UI.
- Multi-instance Pub/Sub, webhook deduplication, late-leave protection and periodic reconciliation repair missed events.
- Screen sharing uses safe video-only fallback when system audio cannot exclude Vatrushka output.

## Reliability and operations

- Email notification delivery is durable and idempotent through the transactional outbox.
- The dedicated observability stack includes Prometheus, Grafana, Loki, Alertmanager, Blackbox and private agents; production cutover remains a separately verified infrastructure step.
- CI runs real PostgreSQL/Redis integration tests, renderer/Electron behavior, 33 Windows visual scenarios and bundle budgets.

## Data and rollout

- migration `0025_mean_emma_frost` adds the unique durable-email outbox index;
- migration `0026_odd_wild_pack` adds server visibility, profile cover storage and the public-server index;
- Redis voice keys are recoverable and may be rebuilt from LiveKit reconciliation;
- production uses `VOICE_MOVE_STRATEGY=controlled-reconnect`, with DnD and moderator move flags enabled only after webhook/readiness smoke checks;
- rollback restores the previous server revision and updater feed; the additive PostgreSQL columns/indexes remain safe for the previous binary.
