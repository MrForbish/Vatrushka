# Vatrushka 0.5.0

Version 0.5.0 replaces the former landing screen with a personal Home dashboard and completes the removal of legacy standalone rooms. The release keeps persistent servers and their text/voice channels as the only collaboration model.

## User-facing changes

- Home now shows Continue, Active Spaces, Recent Activity, audio readiness, onboarding and the current profile in one responsive workspace.
- Dashboard data is cached locally and refreshed when server, channel, message and presence state changes.
- Audio readiness uses the selected Windows microphone and reports permission and input level without opening a second capture stream during an active call.
- Voice presence, member moves, text notifications, attachment-only messages, image previews and the expanded reaction picker are integrated with persistent server channels.
- Manual join-by-code UI and standalone room flows are no longer available.
- Server and direct messages now use canonical PostgreSQL conversations with authenticated WebSocket delivery, Redis Pub/Sub, transactional outbox and HTTP reconnect reconciliation.
- Direct messages expose sent/delivered/read, optimistic retry and first-unread navigation; notification preferences support user, server and conversation scopes with strict DND.
- Server/user settings are backed by real API data, including appearance, moderation, audit, profile/avatar/username/bio, privacy, blocking and account lifecycle.

## Validation

- TypeScript typecheck and ESLint.
- Shared, API and renderer unit tests.
- Storybook interaction and accessibility tests.
- Windows visual regression for Home, profile drawer, auth, voice, media and security states.
- Electron E2E, migration consistency and production bundle budget checks.

## Deployment

This release applies the complete checked migration chain through `0022_square_luminals`. `0012_remove_legacy_rooms_contract` intentionally drops only retired standalone rooms; later additive migrations add Home activity, settings, identity, presence, canonical messaging, notification preferences, outbox and durable S3 cleanup jobs. Persistent server channels and `channel_screen_share_leases` remain intact.

Create a PostgreSQL backup before updating the API. Build and start the production Compose stack, verify `/health/ready`, then publish `Vatrushka-Setup-0.5.0-x64.exe` and its blockmap before atomically replacing `latest.yml`. Installed 0.4.x clients can update in place; portable users must replace their executable manually.
