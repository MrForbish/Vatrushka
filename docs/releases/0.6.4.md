# Vatrushka 0.6.4

Version 0.6.4 completes the private production-observability slice and moves the canonical build and release process to self-managed GitLab CI.

## Added

- low-cardinality API request, latency, readiness and Node.js runtime metrics;
- private Prometheus and Grafana services with provisioned datasource and production overview dashboard;
- node, cAdvisor, PostgreSQL, Redis and blackbox exporters;
- 14 initial alert rules for API availability/latency/errors, messaging outbox, Redis, PostgreSQL, host disk and TLS expiry;
- an operational runbook covering private access, retention, verification and rollback.

## Changed

- GitLab is the canonical repository, Merge Request and CI/CD platform;
- Linux verification/integration and Windows Electron/visual/package jobs run on self-managed project runners;
- Prometheus and Redis exporter images use their official Quay registry to avoid Docker Hub rate limits;
- the public Caddy `/metrics` route returns `404`; Prometheus scrapes the loopback API endpoint directly.

## Operations

- no PostgreSQL migration, Redis key migration, S3 lifecycle change or breaking API contract is introduced;
- create `infra/observability/.env.observability` with a random Grafana administrator password before starting the stack;
- do not open monitoring ports in UFW or the Timeweb firewall; use the documented SSH tunnel;
- monitor the first seven days before tightening thresholds or configuring an external technical alert receiver;
- rollback stops only the separate observability Compose project and preserves its named volumes unless explicitly removed.
