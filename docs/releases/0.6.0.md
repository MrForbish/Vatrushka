# Vatrushka 0.6.0

Version 0.6.0 completes the messaging, settings, presence and notification roadmap on top of persistent servers and channels.

## User-facing changes

- Canonical server and direct-message history now supports upward pagination, optimistic retry, edits, tombstones, attachment-only messages, authenticated image previews, reactions and first-unread navigation.
- Structured user, role and `@everyone` mentions are validated by the API and remain correct after renames.
- Direct messages expose sent, delivered and read state; realtime reconnect reconciles missed messages and read cursors.
- Notification preferences are available at user, server and conversation scope, including quiet hours, mute windows, preview privacy and strict DND delivery suppression.
- User settings cover profile/avatar/username/bio, presence, audio devices, privacy/blocking, password/2FA, sessions, email, export and delayed account anonymization.
- Server settings cover appearance, members, roles, channels, invite links, moderation, audit log, ownership transfer, archive and permanent deletion.
- Redis-backed presence works across concurrent desktop sessions and respects invisible status and privacy rules.
- The updater stays hidden when no release exists and defers restart while a voice connection is active.

## Platform and operations

- Authenticated WebSocket delivery uses Redis Pub/Sub and a PostgreSQL transactional outbox.
- Private Timeweb S3 attachments have durable cleanup jobs, retries and a database trigger that also covers cascade deletion.
- `GET /metrics` exposes technical Prometheus metrics for messaging, WebSocket, outbox, Redis and notifications.
- The Windows production build enables routed settings and presence and targets `https://api.myvatrushka.ru`.

## Validation

- ESLint and TypeScript typecheck.
- Shared, API, renderer and real PostgreSQL/Redis integration tests.
- Storybook interaction/accessibility tests and Windows visual regression.
- Electron E2E, migration-chain validation, production build and bundle budgets.

## Deployment

Back up PostgreSQL before rollout. Apply the complete migration chain through `0023_attachment_cleanup_trigger`, verify Redis and the private S3 canary, then check `/health/live` and `/health/ready`.

Publish `Vatrushka-Setup-0.6.0-x64.exe` and its blockmap before atomically replacing `latest.yml`. Installed 0.5.0 NSIS clients can update in place; the unsigned package may still show a Windows reputation warning.
