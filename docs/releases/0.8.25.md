# Vatrushka 0.8.25

Production delivery hotfix.

## Fixed

- The protected production candidate job explicitly targets the dedicated
  Linux runner instead of relying on untagged-runner availability.
- Candidate manifests and checksum sidecars are created with the ownership
  and modes required by the root-owned deployment wrappers.
- The updater publication input set is normalized before transfer, so the
  stable feed remains protected from group- or world-writable artifacts.
- Observer SSH key material is normalized and validated before deployment.
- The deterministic Windows compact-shell visual baseline is refreshed after
  a verified self-managed-runner rendering drift of 24 pixels.

## Migration impact

- PostgreSQL migrations: none.
- Redis keys: none.
- S3 lifecycle: none.
- Breaking changes: none.

## Release evidence

The protected tag promotes checksum-bound immutable candidate artifacts, runs
production preflight and Observer verification, and publishes the stable
updater only after those stages succeed.

## Rollback

Use the protected `rollback-production-runtime` job to restore the prior
checksum-verified candidate. No destructive database down migration is
performed.
