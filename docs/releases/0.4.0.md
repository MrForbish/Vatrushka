# Vatrushka 0.4.0

Версия 0.4.0 объединяет продукт вокруг постоянных серверов/каналов, снимает поддержку входа без пароля и гостевых комнат, а также вводит возможность локальных обновлений desktop с самостоятельным хостингом.

## Критические изменения продукта

- `/api/v1/auth/request-code` и `/api/v1/auth/verify-code` больше не существуют. Пользователи аутентифицируются с помощью пароля и электронной почты/TOTP/второго фактора восстановления.
- `/api/v1/rooms/**` больше не существует. Голос и демонстрация экрана доступны только через голосовой канал сервера.
- Deep links использовать `vatrushka://server/ABCD2345`; `vatrushka://join/ABC234` отклонен.
- Учётная запись базы данных без хэша пароля больше не может войти в систему. Известная учётная запись владельца платформы была перенесена до этого изменения.

Старые таблицы room, guest-session и legacy lease намеренно сохраняются для безопасности отката. Ни один маршрут или сервис не может создавать или читать их в версии 0.4.0, и никакая деструктивная миграция не вводится.

## Desktop обновить модель

Установленная сборка NSIS читает общий канал обновлений по адресу `https://api.myvatrushka.ru/updates`. Она проверяет наличие обновлений вскоре после запуска и каждые четыре часа, автоматически загружает более новую версию пакета, сообщает о ходе выполнения и запрашивает у пользователя перезапуск. Готовое обновление также устанавливается при обычном выходе из приложения. Разработческие и портативные сборки не обновляются автоматически.

Лента содержит:

- `Vatrushka-Setup-<version>-x64.exe`;
- `Vatrushka-Setup-<version>-x64.exe.blockmap`;
- `latest.yml`, загружен последним.

Поскольку версия 0.3.0 не содержала updater, переход на версию 0.4.0 требует одного последнего ручного запуска установщика. Обновления после версии 0.4.0 можно устанавливать на месте.

## Обновление сервера

1. Создайте резервную копию PostgreSQL и сохраните предыдущий коммит/изображение.
2. Загрузите 0.4.0 и выполните `npm ci`, `npm run db:check`, `npm run lint`, `npm run typecheck`, `npm run test` и `npm run build`.
3. Создайте `/opt/vatrushka/updates` перед началом Caddy, чтобы его привязка только для чтения корректно разрешалась.
4. Перезапустите/восстановите API и Caddy, затем проверьте `/health/ready`.
5. Подтвердите, что устаревшие конечные точки auth и room возвращают 404.
6. Создавайте артефакты Windows с production API URL. Сначала загрузите setup/blockmap, а `latest.yml` в конце.
7. Проверьте `https://api.myvatrushka.ru/updates/latest.yml`, установите версию 0.4.0 вручную и держите предыдущий установщик доступным во время проверки.

## Откат

Восстановите предыдущий коммит/образ приложения и перезапустите API/Caddy с той же базой данных. Миграция схемы вниз не требуется. Учтите, что откат к версии 0.3.0 повторно включает устаревшие маршруты без пароля/для отдельной комнаты, поэтому он должен быть временным и с контролем доступа. Восстановите предыдущий `latest.yml` или удалите метаданные обновления перед откатом, чтобы избежать уведомления о версии клиента, несовместимой с откатанным API.

## Контрольный список проверки

- регистрация пароля и вход с помощью пароля + email/TOTP/восстановления работают; устаревшие маршруты без пароля возвращают 404;
- создание/присоединение к серверу, текстовые/голосовые каналы, роли, сообщения и личные сообщения работают;
- захват монитора/окна, аудио приложения и отключение/регулировка громкости зрителя остаются независимыми от голосов участников;
- выбор ввода/вывода изменяет активные устройства LiveKit;
- аренда канала отклоняет одновременное совместное использование экрана и восстанавливается после истечения срока/вебхука;
- Сборка NSIS создаёт установку, блоккарту и `latest.yml`; переносимая сборка остаётся запускаемой;
- Обновление ленты доступно через HTTPS, а подготовленная более высокая версия достигает состояния готово/перезапуск UI;
- UI остается доступным с клавиатуры и пригодным для использования при масштабировании Windows 100%, 125% и 150%.

## Известные ограничения

- установочные файлы и обновления ещё не подписаны кодом, поэтому Windows SmartScreen может предупредить;
- портативные сборки требуют ручной замены;
- реальный SMTP, NAT/TURN, захватывающие устройства и обновление с версии на версию требуют ручной матрицы выпуска;
- Постоянные списки банов, присутствие в реальном времени и восстановление пароля остаются будущей работой.
