# Vatrushka 0.4.0

Version 0.4.0 consolidates the product around persistent servers/channels, retires passwordless and guest-room compatibility, and introduces self-hosted in-place desktop updates.

## Breaking product changes

- `/api/v1/auth/request-code` and `/api/v1/auth/verify-code` no longer exist. Users authenticate with a password and email/TOTP/recovery second factor.
- `/api/v1/rooms/**` no longer exists. Voice and screen sharing are available only through a server voice channel.
- Deep links use `vatrushka://server/ABCD2345`; `vatrushka://join/ABC234` is rejected.
- A database account without a password hash can no longer log in. The known platform-owner account was migrated before this change.

The old room, guest-session and legacy lease tables are deliberately retained for rollback safety. No route or service can create or read them in 0.4.0, and no destructive migration is introduced.

## Desktop update model

The installed NSIS build reads a generic update feed at `https://api.myvatrushka.ru/updates`. It checks shortly after startup and every four hours, automatically downloads a newer package, reports progress and asks the user to restart. A ready update also installs during a normal application quit. Development and portable builds do not auto-update.

The feed contains:

- `Vatrushka-Setup-<version>-x64.exe`;
- `Vatrushka-Setup-<version>-x64.exe.blockmap`;
- `latest.yml`, uploaded last.

Because 0.3.0 did not contain an updater, the move to 0.4.0 requires one final manual installer run. Updates after 0.4.0 can be delivered in place.

## Server upgrade

1. Back up PostgreSQL and keep the previous commit/image.
2. Pull 0.4.0 and run `npm ci`, `npm run db:check`, `npm run lint`, `npm run typecheck`, `npm run test` and `npm run build`.
3. Create `/opt/vatrushka/updates` before starting Caddy so its read-only bind mount resolves correctly.
4. Rebuild/restart API and Caddy, then verify `/health/ready`.
5. Confirm retired auth and room endpoints return 404.
6. Build Windows artifacts with the production API URL. Upload setup/blockmap first and `latest.yml` last.
7. Verify `https://api.myvatrushka.ru/updates/latest.yml`, install 0.4.0 manually and keep the previous installer available during validation.

## Rollback

Restore the previous application commit/image and restart API/Caddy against the same database. No schema down migration is required. Be aware that a rollback to 0.3.0 re-enables the retired passwordless/standalone-room routes, so it should be temporary and access-controlled. Restore the previous `latest.yml` or remove the update metadata before rollback to avoid advertising a client version incompatible with the rolled-back API.

## Verification checklist

- password registration and password + email/TOTP/recovery login work; retired passwordless routes return 404;
- server create/join, text/voice channels, roles, messages and direct messages work;
- monitor/window capture, application audio and viewer mute/volume remain independent from participant voices;
- input/output selection changes the active LiveKit devices;
- channel lease rejects a concurrent screen share and recovers after expiry/webhook;
- NSIS build creates setup, blockmap and `latest.yml`; portable build remains launchable;
- update feed is reachable through HTTPS and a staged higher version reaches the ready/restart UI;
- UI remains keyboard-accessible and usable at Windows scaling 100%, 125% and 150%.

## Known limitations

- installers and update artifacts are not code-signed yet, so Windows SmartScreen may warn;
- portable builds require manual replacement;
- real SMTP, NAT/TURN, capture devices and a version-to-version update require the manual release matrix;
- persistent ban lists, realtime presence and password recovery remain future work.
